The Russian Empire in Color

Colorizing the Prokudin-Gorskii glass-plate collection via alignment.

lucas zheng · github.com/3LucasZ/cs180-showcase · P1 source code

Problem

I am very thankful to Prokudin-Gorskii for taking these glass plate images. We can realize what the Russian Empire looked like in the past. The glass plates (we assume) correspond to Blue, Green, and Red. However, if you try to place the plates on top of each other, it looks really off.

We need an algorithm to align them. This will take some experimentation. They seem to be rotated correctly, so we just need to shift each image x, y to align.

Naiive idea: single-scale alignment

We perform our alignment algorithm twice: align green to blue first, then align red to blue. Then, all 3 glass plates will be aligned as a single image. The most natural, naiive idea is to align an image with another image via brute force search over every single possible (x,y) shift alignment. This will take very long if we try every single shift. Luckily, it doesn't seem like we have to shift too much, from our example above. For a small image with a small shift like our example above, it suffices to just check shifts in the x and y direction within [-w, w] pixels. We try a half-width value of w=32. 2 of the 3 images align properly from this experiment.

Pyramids

Unfortunately, this did not work on the Cathedral, and will certainly not work on the much larger .tif images (~70MB each!) since shifts of e.g 32 pixels is not enough. We will need a more efficient and powerful algorithm to align them.

So here's a really cool recursive algorithm idea!

If we take the large images and downsample it really small, our algorithm above would work. However, when upscaling them back to original size, we find that the alignment was very coarse. There are still thousands of possibilities of a more finer alignment after upscaling. However, the number of possibilities has drastically reduced. downsample the 2 images we want to align until really small. Downsampling

I wanted to note that I used the naiive downsampling kernel for above: [1 1 | 1 1] / 4. It would have been better to downsample using a Gaussian filter, but this still yielded good results.

The Sobel Prize

The emir is quite stubborn and not lining up... We need a more clever approach to make it work.

One observation is that the color intensities are fundamentally way too different in between images, so even though we normalize them, they won't line up via NCC properly. Our idea is to make an outline of the emir instead of the raw image itself. This is doable via image partial derivatives and gradients. The kernel: [-1, 1] can be used to find the horizontal edges. It's transpose can be used to find the vertical edges. Taking the magnitude, gives us the gradient:

Each of the 3 glass plates looks much more similar now, and it seems more feasible that they will successfully line up.

Note: We could probably do better: smooth first to remove noise before doing edge (partial derivative) detection. There are also other techniques: Canny edge detection, laplacian edge detection. But, the emir is lining up perfectly now!

Normalize each color channel disjointly: make R, G, B each take up the entire range. E.g if Red took up [63, 128], we stretch the colors to take on the entire [0, 255] intensity range. I found that it looked nicer than normalizing all channels together.

Automatic white balance: we take the prior that the brightest objects should be white in the image. To be honest, I don't think this did anything.

We sharpen the image, to try to bring out more detail.
