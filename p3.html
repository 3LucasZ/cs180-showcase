Part A: Exploring the Power of Flow Models

1.1: Constructing Noisy Training Inputs

We can create a noisy image with certain "intensity" of randomness by interpolating it with noise. \[ x_t=(1-t)\epsilon+t x_1 \]

1.2: Classical Denoising

We can try to denoise the image with the classical computer vision method of Gaussian blurring the noise away. However, the results are not good; a lot of the image's details gets destroyed in the process.

1.3: One-Step Denoising

We use a pre-trained denoiser model to try to denoies the image. We guide the model with the prompt "a high quality photo". The velocity produced by the model is added via: \[ \hat x_1=x_t+(1-t)v_\theta(x_t,t,c) \] This does better, but it still does not recover the full details of the image. The model unfortunately averaged out some of the details in the scene, with worse results the more noisy the image is.

1.4: Visualizing Velocity

We compare the model's predicted update \[ (1-t)\hat v_t \] against the true update \[ (1-t)v_{gt}=x_1-x_t \] which suggest that low frequency data between the 2 are similar, but edges are different.

1.5: Iterative Denoising with Euler Sampling

Instead of doing 1 large velocity step, we break it up into many small steps (more accurate Euler integration approximation): \[ x_{t+h}=x_t+h\,v_\theta(x_t,t) \] with the velocity recomputed at every state. Here, we start from \(t=0.50\) input, and perform 25 steps of \(h=0.02\).

As seen in the comparison below, the final image does better at preserving the detail the one-step estimate lost.

1.6: Generating Images from Noise

Here, we use the model to generate images from pure noise, without giving it a starter noisy image. We use the same prompt: “a high quality photo”. Below, shows that the model's default idea of a photograph, before any particular guidance, is a human. A lot of the images are very creepy, and I am sorry.

2.1: Classifier-Free Guidance

Classifier-free guidance is a trick to make the prompt matter more during image generation and make the image results better. \[ v_{cfg}=v_c+w(v_c-v_u) \] Below we can see that the generated images have better alignment to the prompt (more realistic looking people). Larger w means more accurate-looking images, but less diversity of images.

3.1: Image-to-Image Editing

In this experiment, for different t, clean image noised to the t, \[ x_{t_s}=(1-t_s)\epsilon+t_s x_1 \] the euler integration sampler of velocity runs from \(t_s\) to \(1\). Small \(t_s\) starts with more noise -> model has more creativity to rebuild the image. Large \(t_s\) starts closer to the clean image -> image is less changed.

3.2: Text-Guided Image Editing

For this experiment, we try creative prompts which describe an edit we want to perform to the image. The start time controls how much the prompt is considered (i.e weighted). At \(t_s=0.50\) -> output looks very much like the original image. At \(0.02\) -> the prompt mainly decides the output image.

3.3: Visual Anagrams

Here, we generate images which have a completely different scene when flipped upside down. The algorithm is that the velocity sampler gets the conditional velocity for prompt \(a\) on the current state, the conditional velocity for prompt \(b\) on the rotated state, the second velocity is rotated back, and the two velocities averaged:\[ v=\tfrac{1}{2}\big(v_{cfg}(x,t,c_a)+F\,v_{cfg}(F x,t,c_b)\big) \]

3.4: Hybrid Images

This is kinda like the hybrid images in project 2, except with GenAI, and much cooler! The algorithm is that the velocity sampler takes the low frequencies of prompt \(a\)'s velocity and combines it with the high frequencies of prompt \(b\)'s velocity. \[ v=lopass(v_a)+hipass(v_b) \]. Thus: prompt \(a\) gets to create the distant low frequency data while prompt \(b\) determines the close-up high frequency detail.

1.2.2: Out-of-Distribution Testing

We test to see if the model can denoise images not in it's training distribution; i.e images with different noise level from \(\sigma=0.5\). Near \(0.5\) down to \(0.0\) the digit is recovered; at \(0.6\) and above it kinda finds the shape but is very noisy. This shows us that a single noise level is not sufficient to generalize the denoiser for all noise levels.

1.2.3: Denoising Pure Noise

Now we train the same network, but the training data is pure noise without any hint of the original image. The loss doesn't have the digit the noise was paired with. Thus, under MSE (like the dull-colored bird example from lecture), the best possible output is roughly the average of all the images in the dataset. Here, we see a blurry 8. Both checkpoints (epoch 1, epoch 5) show a similar output. Further training does not sharpen it; the blur is what the L2 thinks is optimal.

Let's sample, to see the results! Epoch 1: strange symbols. Epoch 5: still weird unrecognizable symbols but closer to digits. Epoch 10: some distinguishable digits emerge, some of them still look really malformed. So far, the model is unconditional; the noise tensor becomes whatever digit the velocity field carries it to by chance (we don't determine it).

2.4: Implementing a Class-conditioned UNet

Now, we pass the class of the image into the model. It is a one-hot encoded vector. It is passed through a pair of FC blocks, similar to what we did last step for time, and added on top of the time embedding.

During training, the class vector is dropped with probability \(0.1\), which teaches the network to also predict unconditionals. This way, we can do guidance (e.g CFG) at sampling time. Our goal is that the model can produce class-conditional velocity and the unconditional velocity at any state.

Finally, for this last experiment below, we remove the exponential scheduler from the Adam optimizer. Instead, we use a constant learning rate of \(3\times10^{-3}\) on the Adam Optimizer. We chose this because it is in between the scheduler's start of \(10^{-2}\) and final of \(10^{-3}\). This way, we can get both worlds of fast early progress and granular late steps. The loss is very slightly higher, but generation looks just as good!
